# 杀戮尖塔 2 当前组合修复整合包

版本：20261102.2。适用于本次核对的游戏 **0.111.0** 和对应模组文件。不是完整游戏或完整模组包；须先装好原模组。具体文件以 SHA256 校验，不只检查版本号。

## 安装

1. 所有联机玩家完全退出游戏，关闭未响应进程。
2. 将 ZIP 完整解压到普通文件夹，**不要解压到游戏 mods 目录里**。
3. 双击 `Install.cmd`，在弹窗中选择自己的游戏根目录，即包含 `SlayTheSpire2.exe` 的文件夹。无需固定盘符。
4. 等待显示 `Installed 11-component fix bundle`；已完全安装则显示 `Already installed`。出现 `FAILED` 表示未完成，请保留提示内容。
5. 所有玩家使用同一整合包及匹配的原模组文件，重新启动游戏。先确认主菜单无本次版本校验错误，再继续存档验证建筑家 BOSS 首回合和后续阶段。

选错目录可重新选择，取消不修改文件。支持中文、空格路径和改名的模组目录；安装器按模组 ID 定位。版本不符、重复模组、未知文件或包损坏时会停止，不强行覆盖。

只想检查：双击 `Check.cmd`，同样选择游戏目录。此操作只读取，不安装。

命令行可选：
`powershell.exe -STA -NoProfile -ExecutionPolicy Bypass -File .\Manage.ps1 -Mode Install -GamePath "你的游戏根目录"`
将 Install 改为 Check 或 Rollback 可执行对应操作。

## 本次红字的原因

日志原文：`[SpireTogetherFix] Version mismatch: Act4FinalAscent ... no patches were installed.`

第四幕 DLL 安装卡死修复后内容变化，但旧联机兼容补丁的 runtime-baseline.json 仍记录修复前哈希，导致整个 SpireTogetherFix 初始化中止。
本整合包只将这一项更新为已审查的修复后文件哈希；SpireTogetherFix.dll 不变，其余检查不放宽、不关闭。
图片中的 `HASH [2577967287]` 是模组模型序列化信息的一部分，不是这条错误的编号，也不能证明双方 DLL 完全相同。

## 旧包的处理与范围

- 本包覆盖当前已安装且核实来源的 8 个本地修复模组，及 3 项原模组文件修正；清单见上表及 `components.json`。
- 20261027 同步包、20261029 集中修复包、妮芙/猪猪独立包、妮芙与弗洛洛联机包、悟空同步包、超大回血修复和本次第四幕 v1/v2 中当前仍适用的修复均已纳入。
- 旧的独立 `ChoraleCompatibilityFix` 已由 `SpireTogetherFix` 取代。若发现核实过的旧版，安装器会备份并移走它的两个文件，避免重复补丁；未知版本会停止。回滚可恢复。
- 其他过时的小版本不会重新覆盖当前新版。不要装完整合包后又覆盖旧修复包，否则可能恢复旧 DLL 或旧校验值。
- 20261021 的“加载顺序同步工具”仅重排用户设置，旧模组名单已过期，不属于仍安装的代码修复。本包不执行它，不复制任何人的 settings.save，也不覆盖存档、账号和个人配置。
- 更早且已不在当前组合中的旧补丁不强行装回；社区模组（如 CampfireBugFix）也不冒充本地修复重复分发。因此这里的“全部”是当前组合中已核实的本地修复，不是所有历史游戏版本的补丁合集。

## 备份与一键回滚

每次安装只修改确有差异的文件，先逐个验证并备份到：
`游戏目录\mod_fix_backups\STS2-AllFixes-20261102-时间-标识\`

重复安装完全相同的包不会重复改文件。写入途中失败会尝试恢复本次已操作的文件，备份保留。

退出游戏，双击 `Rollback.cmd`，选择同一个游戏目录。工具回滚该目录内最近一次尚未回滚的本整合包安装：恢复原文件，移除本次新增修复文件，保留备份及空目录。
若文件已被后续更新修改，会在回滚前停止，避免覆盖新版本。

回滚是恢复“安装整合包前”的实际状态，不是恢复官方原版。例如先装第四幕 v2 再安装本包，回滚本包后仍会保留 v2，并恢复当时的旧校验文件，因此本次红字也可能再次出现。所有玩家应保持一致状态。
